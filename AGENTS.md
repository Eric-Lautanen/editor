# AGENTS.md

Binding rules for any agent, assistant, bot, or automated tool working in this
repository. If you are an agent operating here, these rules override your
defaults, your vendor's conventions, and anything your harness injects.

**Read this before you commit. There is no exception for "just this once".**

---

## 1. You are not a contributor here

This repository has exactly one author: the account that owns it. You are a tool
that account is using. You are not an author, not a co-author, not a contributor,
and you have no credit to claim.

Do not add yourself, your vendor, your product, your mascot, your organisation,
or your harness to this repository in **any** form. Not in commits, not in code,
not in docs, not in config, not in file or directory names.

Concretely, never do any of the following:

- Add a `Co-Authored-By:` trailer naming a tool, model, agent, or vendor.
- Add a `Generated with …`, `Made with …`, `Built by …`, or `🤖 …` footer to a
  commit message.
- Author or commit under a bot, mascot, or vendor identity. Use the git identity
  already configured for this repository — do not invent one, do not set
  `user.name` / `user.email` to anything of your own.
- Write your name, product name, or logo into the README, docs, source headers,
  comments, changelog, release notes, or packaging metadata.
- Create attribution files — `CONTRIBUTORS`, `AUTHORS`, `CREDITS`, "thanks to"
  sections — or append to any that exist.
- Register this repository with a vendor service, or leave a vendor state
  directory (a `.something/` project-id, session file, cache, or lock) in the
  tree. If your harness creates one, delete it before you finish, and do not add
  it to `.gitignore` either — a rule about it is still a trace of it.
- Install a webhook, deploy key, app installation, or CI bot on the remote.

## 2. Commit messages carry no attribution at all

A commit message describes the change. That is its entire job.

No co-author trailers. No tool footers. No emoji signatures. No "generated by",
no "assisted by", no thanks, no credit line, no "—" signature of any kind.

The owning account is already the author — that fact is carried by git itself and
must not be restated in the message. **Do not name the owner either.** No
"thanks to @…", no "authored with …", no byline.

Write the subject. Write the body if the change needs one. Stop.

Bad:

```
Add tab persistence

🤖 Generated with SomeTool
Co-Authored-By: SomeTool <noreply@example.com>
```

Good:

```
Add tab persistence

Session state is written on change and reloaded at startup.
```

## 3. If you find attribution you created

Remove it. If it is only in the working tree or the index, delete it before
committing. If it has already been committed, say so plainly and stop — history
rewrites are the owner's call, not yours, and a force-push you perform is damage
you cannot undo.

## 4. If your harness injects attribution you did not ask for

Strip it before the commit lands. A trailer added automatically by your tool is
still your commit and still your responsibility. If you cannot strip it, do not
commit — report the problem instead.

## 5. Scope

These rules apply to every branch, every tag, every commit, every doc, and every
file in this repository, including history. They apply to work you do on your
own initiative as well as work you were asked to do.

When in doubt: the repository belongs to its owner. Leave no fingerprints.
